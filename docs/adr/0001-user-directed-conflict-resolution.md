# Preserve concurrent task changes for user-directed resolution

When multiple devices independently change the same task, BetterWeekToDo preserves the resulting versions as a sync conflict instead of automatically merging fields or choosing a winner. The conflict UI lets the user select fields for a single merged task or split the versions into separate task identities, because changes that appear structurally independent can be semantically incompatible—for example, completing “Buy milk” on one device while changing it to “Buy oat milk” on another. Deletion is treated as a version: resolving toward deletion removes the original task, while splitting a delete/change conflict keeps the original deleted and gives the surviving changed version a new identity. Deleting a custom list while another device changes its contents is likewise reviewed: restore the list, explicitly delete its tasks, or move them before deletion, with restoration as the non-destructive default.
