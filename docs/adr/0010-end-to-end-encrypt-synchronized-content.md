# End-to-end encrypt synchronized planner content with MLS

Clients protect planner content with Messaging Layer Security (MLS) before synchronization, while the server stores opaque application messages and only the limited sync metadata required for routing: memberships, authorized installations, opaque identifiers, message sizes, timestamps, cursors, and MLS epochs. Task/list semantics, completion, assignments, recurrence, personal placement, and linked-task details remain encrypted. During an account's first sign-in, before it can receive or create synchronized, group, or account-bound planner data, the user must save the locally generated 24-word recovery key, using copy or a downloadable/printable recovery sheet if desired. The app warns that copying key material reaches the system clipboard and offers to clear it after sixty seconds where the platform permits. Re-entering the fixed six-word confirmation portion and acknowledging that neither administrators nor password reset can recover planner content are required before activation. A new installation restores encrypted MLS state through the recovery key or a short-lived QR pairing request approved by an already authorized installation; the service cannot recover data when both paths are unavailable. An authorized installation may replace a lost or exposed recovery key after fresh authentication and confirmation of the replacement; the old key cannot restore future MLS epochs, although it may still decrypt historical exports protected by it. This deliberately accepts permanent data loss after loss of all key material in exchange for preventing the application server, database, and backups from reading task content.
